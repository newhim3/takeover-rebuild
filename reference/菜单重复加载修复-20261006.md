# 菜单重复加载修复（r6）

本轮按用户要求处理再次进入菜单的等待，不修改战斗、AI 或已认可的界面排版。初次打开尚未访问过的页面仍可产生下载和解码。

## 已确认的文件与代码问题

开始、存档、战役菜单仍直接使用含内嵌位图的复杂 SVG。前几轮战场图集优化没有覆盖这些菜单。服务器此前已有一小时静态资源缓存和 ETag，并不是每次返回都必然重新下载；旧菜单仍需要浏览器处理 SVG 文本、内嵌位图和滤镜，场景切换也没有主动保留近期图片对象。没有获取实际浏览器性能时间线，因此不能断言每次卡顿都来自同一个环节。

| 原素材 | SVG 字节 | gzip 后字节（离线计算） | 本次无损 WebP 字节 |
| --- | ---: | ---: | ---: |
| 标题背景 | 3,736,035 | 2,810,651 | 1,246,214 |
| 存档背景 | 5,134,464 | 3,833,628 | 1,192,002 |
| 冰国战役旗帜 | 2,196,675 | 1,632,130 | 302,918 |
| 第一战役地图 | 1,403,428 | 979,322 | 860,450 |

这些数字不代表实测网络耗时。部分小 SVG 的缓存图片反而更大；本轮同时减少菜单 SVG 解析，不声称所有文件压缩率都相同。完整逐文件记录见 `native-menu-cache-audit.json`。

## 改动

- 185 个已有静态原素材导出为无损 WebP 缓存，保持完整透明范围和原位置。常规以原逻辑尺寸的两倍导出，并限制最大尺寸。原 SVG 保留；没有生成新 UI 或改造卡片。
- 标题、存档、旗帜、战役地图、条令、关卡弹窗与结算素材通过同一映射访问。只加载访问到的内容，不在启动时预载全部 185 个文件。
- 近期访问的图片对象保留在页面内，并触发异步解码。保留对象按最近使用顺序淘汰，估算像素内存上限 64 MiB、最多 96 张；这个上限不包含浏览器自身纹理与可见 DOM 占用。浏览器仍可能自行回收解码缓存。
- 保留结算统计表格和交互；页头徽章换为对应国家原 MissionOver 结算徽章，原统计条、行底板和按钮接入缓存。
- 更新入口文件版本为 r6；只需刷新一次取得新代码。服务端未重启，无需为本轮修改重新创建房间。

## 已做的定点检查

- 变更 JavaScript 与缓存清单语法检查通过；入口与 CSS 文件引用存在。
- 缓存检查脚本确认同一菜单访问两次只创建一个 Image、触发一次加载/解码调用；对象淘汰后估算保留像素量不超过预算。
- 185 个缓存文件存在；标题、第一张战役地图与冰国结算行的可见像素，与原 SVG 在相同尺寸的离线栅格化结果一致。
- 本地入口提供 r6，WebP 返回正确 MIME；相同 ETag 的条件请求返回 304、正文 0 字节。
- 当前临时公网入口返回 r6 和新版旗帜图片，均为 HTTP 200。

没有重复跑战役或浏览器游玩，也没有实测返回页面耗时、FPS 或跨网络对战。本轮检查证明资源路径、缓存调用和原素材栅格化对应，实际操作体验由用户反馈。
