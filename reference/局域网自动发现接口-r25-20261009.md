# 局域网自动发现与本地中继

本地启动器为每台电脑启动自己的游戏服务，浏览器打开本机页面。地图、原 UI 和动画仍从本机加载；加入其它电脑的房间时，仅房间 HTTP 操作及 WebSocket 状态转发到实际房主，战斗仍由房主统一计算。无需将房主网址复制给客人。

## 页面接口

- `GET /api/lan/peers`：返回 `lanProtocol: 1`、`enabled`、`degraded`、`error`、`self`、`peers`。`self` 包含 `id/name/build/port/rooms`。每个 peer 包含 `id/name/build/address/port/rooms`，`address` 是 UDP 实际来源地址组成的只读地址，界面无需要求玩家输入。`build` 来自交付构建标识，仅接受合法 16 位小写十六进制，缺失或非法为 `null`。未知或不同版本仍可发现，但加入及中继会要求双方同一版本，避免不同素材索引造成显示错位。
- 公开房间仅包含 `code/hostName/phase/players/maxPlayers/canJoin/map`。`players` 是人数，`maxPlayers` 固定 4。发现报文和列表不包含身份 token、条令、实际经济、指令或战场快照。
- 客人的房间请求使用 `/api/lan/peer/<id>` 前缀，例如 `POST /api/lan/peer/<id>/api/rooms/ABC123/join`。认证、指令等沿用原房间接口。
- WebSocket 使用相同前缀，例如 `ws://127.0.0.1:<本机端口>/api/lan/peer/<id>/api/rooms/ABC123/socket?token=<身份密钥>`。SSE 后备事件流也可转发。
- 列表与中继只接受本机回环连接，且 Host 必须为当前端口的 `localhost`、`127.0.0.1` 或 `[::1]`。浏览器 Origin 若存在须与 Host 一致。临时公网入口或其他电脑不能枚举本机邻居或借用中继。

## 发现过程与关闭

实际 HTTP `listening` 后才开启 UDP `44987`，每 3 秒向本机网卡子网广播及 `239.255.43.87` 组播（TTL 1）询问；对端单播返回公开信息。无需端口扫描、DNS 服务或互联网。发现目录最长 12 秒有效，每次转发前重新核对来源 IP 属于本机网卡同一子网。

同机多实例使用共享 UDP 绑定；绑定受占用/权限限制时降级为随机 UDP 端口，继续广播询问并接收单播答复。转发仅允许 `/api/rooms` 的既有方法与路径，不能填写任意目标 URL。HTTP 初次响应超时 10 秒，TCP 连接超时 5 秒，WebSocket 握手超时 8 秒。正常 WebSocket/SSE 不套短响应超时。

`server.close()` 同时关闭发现 UDP、定时器、HTTP 中继代理及升级连接，不保留后台发现句柄。每个服务器的 `network.lanRooms()` 提供公开房间信息。

## 实际限制

两台电脑都要运行本地启动器并连接可互通的 IPv4 局域网。Windows 防火墙需允许游戏服务的 TCP 游戏端口及 UDP 44987，建议只允许专用网络。访客 Wi-Fi、路由器客户端隔离或禁止广播的网络可能阻止自动发现；本功能不解决跨网络公网穿透。

实现参考 Node.js 官方 [UDP 文档](https://nodejs.org/api/dgram.html) 与 [HTTP 文档](https://nodejs.org/api/http.html)。定点验证结果见 `.tools/r25-lan-check.json`；没有使用长战役模拟，也未声称已在两台实体电脑上完成联机测试。
