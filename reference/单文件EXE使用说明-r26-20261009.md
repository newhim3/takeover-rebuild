# 单文件 EXE 使用说明

日期：2026-10-09。

发布文件为 `dist/城邦征战.exe`。分发时只需把这一个文件交给朋友，不必另外发送素材目录、Node 或 CMD。

双击进入游戏首页，再选择“联机争霸”。双方使用同一份 EXE，并连接同一可互通网络，房主创建房间，朋友点击同网房间加入。原第 7 关默认地图、B 中央高地选项、房主暂停和调速保持现状。

首次运行会显示本地准备进度，将运行资源解包到 `%LOCALAPPDATA%/TakeoverPortable/包哈希前16位/城邦征战`。完整提取后才写入就绪标记；后续启动仅核对标记及少量关键文件，直接复用缓存，不重新解包整套素材。缓存和单人存档各有用途，不能把清除缓存当成清除浏览器存档。

单文件解决分发与启动方式，压缩后的素材容量仍包含在 EXE 内。这是现有网页游戏的本地封装，仍由本地服务统一处理联机，并非 Unity 移植。首次准备进度窗是系统启动提示，没有替换游戏中的原版 UI。

Windows 首次询问网络访问时，允许可信家庭网络的专用网络访问。访客 Wi-Fi 或路由器客户端隔离可能阻止设备互通；单文件不会解除这些网络限制。脚本没有自动修改系统防火墙。更新后的缓存路径不同，先前绑定旧 Node 路径的防火墙规则不会自动跟随。

启动器核对当前前端构建，并通过整包哈希识别仅后端更新的便携版本。跨缓存版本只停止能够核验为本便携包托管的旧服务；核验 PID、创建时间、Node 路径、服务脚本完整命令和包缓存目录。服务重启会结束旧房间，需重新创建。其它目录中的服务不会被擅自关闭。

素材审计见 `reference/素材使用范围与单文件发布-r26-20261009.md`。开发原资料完整保留；发布仅排除有依据的开发源档和中间导出，运行路径、回退资源及尚未确认用途的资源继续保留。代码可达表示运行程序可能加载，不等于每个素材都已经实际播放。

本轮只检查封装格式、实际首次提取、第二次缓存复用、关键文件一致和托管服务判断，没有新增浏览器游玩、长战役模拟或两台实体电脑联机验证。未修改战斗、AI、数值、地图和游戏界面。
