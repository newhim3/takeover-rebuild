# 需求核对：代码证据与仍待完成的部分（2026-10-07，r13）

这份报告只读核对运行代码和既有记录，没有重写敌军策略，没有跑长战役或公网双人实战。代码存在某个机制，不等于所有关卡的画面、胜率和异常情况都已经验证。

## 敌军战斗方式与难度

核对 `enemy-ai.js`、`ai-presets.js`、`difficulty.js`、`unit-rules.js`、`spell-runtime.js` 的 SHA-256，均与 `.tools/r10-ai-baseline.json` 相同。以下策略是此前已经存在的实现，不是本轮又重新设计了一套敌人。

| 用户要求 | 现有代码证据 | 判定和边界 |
|---|---|---|
| 开局十秒发展，遭袭能防守 | 五档难度 `opening:10`；`offensiveOrders`、`maneuverOrders` 在十秒前禁止主动出击；`reserveUnits` 仍处理威胁 | 已有机制。r12 另修正加载时逻辑时间保持零，避免发展期消耗在空白画面中 |
| 越难越聪明，不能凭空增强兵力 | `tacticalLevel` 依次为 0–4；援军预测、分队、反制、救援和施法判断逐级增加；高于普通 `techLead:0`、`initialCastle:1` | 未见难度对单位生命、伤害或持续收入另加倍率。高难度仍保留此前授权的一次性小额资源：困难 +15 金/+5 法力、精锐 +30/+10、噩梦 +45/+15；不能称完全只有决策差异 |
| 普通经济同等，建筑和招兵真实付费 | 普通开局 300 金、70 法力，加同等映射的玩家条令；`buildFor`、`queue`、`upgradeFor` 都检查并扣真实费用 | 普通没有持续免费收益或免费兵。关卡原有据点数不一定对称，更多据点的收入差异仍会存在 |
| 精锐打食人魔、取箱增强实力；噩梦积兵补兵 | 目标评分包含宝箱收益与危险；`lootOpportunity` 不覆盖正在攻城/救援的任务；取箱后升堡偏好分别为 .85/.6；噩梦 `armyFirst` | 是收益和战况判断，不是持续无条件取箱。没有逐场证明每个安全箱子都一定及时领取 |
| 先看守军，再看拆墙耗时 | `targetAssessment` 先计算守军实力，再计算墙体生命/部队攻城 DPS；困难以上预测附近援军到达 | 已有机制，限每目标最多六队、十八秒预测，属于启发式而非完美预知 |
| 不只正面等绝对优势，能骚扰空城 | `maneuverOrders` 寻找可攻击的孤立据点、空虚目标与后排；主目标会比较沿途更近且可夺取的空城 | 已有机制。保留此前稳定任务和随机偏好，没有改变用户调教的进攻方式 |
| 两线遭袭，优先保住还能救的地方 | 威胁按预计倒塌时间、可到场兵力和据点价值排序；困难以上可放弃无望救援；回援承诺保持六秒 | 已有机制；是否在具体双线战局中选择合理仍需实玩反馈 |
| 骑兵、攻城车不单调，也不固定采购配额 | 招募根据远程威胁、拆墙时间、可用兵种、金币与随机偏好判断；有足够现役兵力才短暂等待专用兵种 | 已有机制；不存在固定骑兵/攻城车采购预算。未证明所有关卡都出现理想兵种比例 |
| 受伤避难、支援，驻堡及时迎敌 | 低血量/城外待机伤兵进入恢复集合；安全据点按路径距离选择；`defendingThreat` 识别近敌和指定攻城目标，`defend` 派驻军出战 | 已有机制，也能识别指向城堡的攻城车。没有保证所有特殊角度和人群拥堵都已实玩覆盖 |
| 集结不能把修理、防守、回血部队也算进去 | `reserveUnits` 分出修理、守备、恢复和取箱人员；集结/分队使用 `available` | 已有机制。等待集结并非任何情况下都算 bug，但满员永久停塔外仍需针对现场异常定位 |
| 不频繁左右换令 | 固定随机偏好、旧任务粘性、同一路径不反复重发、分队承诺和回援承诺 | 已有机制；本轮未修改决策调度 |
| 高难度会用法术协同 | `spellTarget` 区分疗伤、增益、控制、召唤、攻城和大招；`spells` 逐档加快检查，验证条令、法力、塔蓄能和目标状态后调用原法术运行时 | 不是只产生法力的空接口。但有法力不代表已解锁或存在合适目标；没有逐场证明最高难度每局都实际施法 |

当前是可解释的规则和评分策略，没有训练机器学习模型，也不能称已经超过人类高手。保护既有风格的后续方向应是观察任务停滞、无效目标和施法机会的实际原因，再补条件；不把“再加算法”本身当成变聪明的证据。

## 法术、兵种与经验

普通法术仍受真实法力限制，没有另造固定时间冷却。终极蓄能只在拥有已修复魔法塔时推进；丢塔清零。黑暗法术来源和映射独立于冰国，黑暗大招按用户覆盖转化场上可转化敌方小队的一半，奇数向下取整；这是自定义平衡，不冒充原表固定数量。

沙虫在 `SpellRuntime.tick` 对敌方部队及城堡都产生伤害；城堡相交按据点半径计算。绿国大招在宣告动画后召唤 `Avatar`，同时播原 `SignOfAdventEffectClass`，不是训练队列逐个造普通兵。四国大招有各自原宣告类与原效果，但完整镜头、命中时序和最终观感应以本轮动画核对及用户实玩为准。

用户指定的三个熟练等级倍率已在 `RANK_SCALE` 明确区分步兵、弓手/法师、骑兵、攻城车。每支击败的非中立敌军提供 50 经验，按实际伤害贡献分配；100/200 经验进入二/三级，最高三级。因此“打两队升一级”指独占两队击杀贡献且没有条令加速的基准，不是参与两次战斗就一定升级。另保留高级城堡直接训练精锐和驻扎缓慢训练，不能声称全部经验都只来源于战斗。

基础兵表来自原记录，但当前另外存在明确自定义：冰国步兵生命乘 1.2、黑暗步兵生命乘 1.1；食人魔生命 520、单次基础伤害 8–10；以及上述用户指定熟练等级倍率。不能把整套最终数值说成原版一字未改。冰国升级步兵的“冻结”实际是攻击概率冻结敌人，原条令记录为 7%/15%，当前中文说明已如此表达，不是防止自己被冻结。

冰国二阶步兵的原生命、编制、攻击间隔和长矛反骑兵能力，与绿国盾墙不是同一种属性；目前的生命修正不能保证在任意阵形、条令、科技和剩余人数下“一队必胜两队”。本轮不擅自再加强数值。原弓手射程、伤害、近战惩罚和盾墙抵抗已在运行规则中消费，但距离视觉与密集战斗命中仍需现场反馈。

## 已认可画面、原素材与还缺的部分

1. **黑暗原战役资料仍缺。** `GAME_DATA.campaigns.Purple` 实际使用 11–18 关，与红国地形关卡相同；黑暗旗徽、条令、单位和法术独立，不等于找到了完整原第四国战役数据。当前关卡说明和地图属于适配，必须继续如实标注。
2. **原 UI 使用不是全覆盖验收。** 目前已有原底栏、招募/建筑管理框、评级冠标、经验进度、城堡/附属建筑动画、悬停交叉双剑、四国结算徽章。数字位置已有冰/黑独立坐标；完整评级 viewBox 已保留下端。静态叠合证据存在，不等于所有窗口尺寸已验收。交叉剑动画和方向死亡已在当前代码接入，不能继续沿用早期报告“只播向下死亡”的旧判断。
3. **仍需核对的自制显示。** 施法光标本轮正在切换原 Cursor 素材；此前简化的弹道、命中线、倒塌烟尘和圈选反馈仍应逐项找原类/帧来源。国家介绍悬停文字目前仍有 CSS 渐变底板；不应笼统宣布“所有 UI 已原版”。本轮呈现修改由相应素材记录说明，机制不因此改变。
4. **B 地形仍是适配。** 地表可切换四国原地面纹理，道路保留 B 的既有画面；没有原版 B 的完整国家山体、树林、道路时间轴，不能把地表纹理替换称为完整原地图帧还原。
5. **原小地图边缘不是全已解决。** 第 7/17/24 关共用遮罩为依据原悬崖修补的产物；r12 镜头按作战区域并留出驻军图标空间。这不等于取得了原版完整遮罩，其他关卡仍要结合用户指出的具体接缝检查。
6. **原素材清单需区别时代。** 2026-10-06 文件数和引用统计是当时的静态审计口径；后续资产打包、宣告图集、方向死亡和光标接入已发生变化。没有重算时不得引用旧“未使用”清单证明它们现在仍未使用，或把打包副本算成新增内容。

加载方面，r12 的定点记录已证明延迟地图期间战斗时间为零，联机未完成地图预热前不发送准备完成，静态资源缓存不因脚本版本变化整库丢弃。新公网域名是新的浏览器来源，仍会重新下载；没有本轮所有入口和全部设备的加载耗时/帧率测量。

已有本地 EXE 是启动现有服务和 Edge 应用窗口的启动器，能减少公网素材等待，不是 Unity 移植，也不能自动消除公网 RTT。

## 不能提前宣布完成的验收

“所有关卡都不存在无解局”和“难度恰到好处”还没有证据。初始地形、城堡数量、可点条令、阵营组合和玩家选择不同，静态代码检查不能推出可赢率。已有机制保留无城堡但仍有部队的反攻空间、资源据点价值、战斗掉队后的保存部队和黑暗半数转换等翻盘变量；它们提供策略机会，不保证任何巨大实力差都能翻盘。

后续应由用户实玩提供具体国家、关卡、难度和对局问题，再对相关目标/条件定位；本轮保留其已调教的敌军出兵、进攻、集结和回援方式。没有为了宣称平衡而修改原据点、增发资源或反复模拟整套战役。
