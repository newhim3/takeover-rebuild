# 开局加载与缓存升级修正（r12）

用户反馈开局直接出兵、地图仍生硬、界面显示慢。本轮没有重写敌军策略：`enemy-ai.js`、`ai-presets.js`、`difficulty.js`、`unit-rules.js`、`spell-runtime.js` 仍与 r10 修改前的 SHA-256 相同。当前 AI 原本仍有十秒发展期；期间可以按已有规则发展和防守，主动出击逻辑仍受开局时间限制。

## 复现出的开局问题

旧入口点击“开始战斗”立即隐藏菜单并开始计时，地图脚本、地形和初始士兵仍异步加载。将地图资源暂缓一秒，实际得到：地图没有准备好，菜单已隐藏，战斗时间已走到 1.1 秒。资源等待超过十秒时，玩家看到画面前，原本的十秒发展期就可能已经过去。

修正后，原关卡信息按钮显示“正在加载素材…”，菜单保持可见；战斗保持暂停，先准备原地图、建筑和初始部队素材并绘制首帧，随后清空逻辑时间累计再开始。加载失败允许在原按钮重试，不新增面板。相同夹具的结果：等待期间战斗时间为 0；地图完成后进入，时间仍为 0，初始敌军保持驻扎、没有进攻指令。记录在 `loading-profile/r12-start-before.json` 和 `r12-start-after.json`。

联机把资源准备放进“准备完成”操作：地图、初始城堡/部队素材及初始原地形完成后才向服务端发送准备消息。单人大厅夹具证明资源未完成时，服务端仍是大厅且玩家未准备；完成后才变为已准备。没有启动实际联机战役模拟。原服务器计算、开局资源、AI 规则和开始条件没有重写。记录在 `loading-profile/r12-lobby-preload.json`。

## 缓存升级问题

上一版将整套资源缓存名称绑定到脚本哈希，更新脚本后删除全部旧缓存，包括没有修改的原 UI 图片。这会导致用户每次试新版本都再经历大量下载。

现在使用独立的持久静态资源缓存，旧缓存内未变化的图片迁移保留；脚本仍按自己的内容版本更新。页面加入构建标识，缓存首页与当前版本不一致时优先取得当前页面，避免把旧页面当成新版本。写缓存失败也不会丢掉已经下载成功的资源。联机 API 与指令依旧不缓存。

`tools/check-cache-upgrade.cjs` 验证了旧原图保留、新首页版本匹配、API 绕过缓存以及缓存写失败后资源正常返回。临时公网域名改变会改变浏览器存储来源，旧域名的缓存不能搬到新域名；这与同一地址下更新脚本保留缓存是两件事。

## 地图取景

上一版按装饰图层的完整外接范围缩小整张地图，原作战视口外的悬崖背面和导出边缘也被展示出来。当前原地图按正常作战区域取景，顶部留出 48 个逻辑单位给驻军标记；不把整块视口外悬崖背面缩进战场。地图像素、道路、据点和国家地形帧没有重画或改位置。B 中央高地继续保留其大地图范围，没有宣称其全部视觉问题已完成。

第 7 关暂停预览：`loading-profile/r12-start-after.png`，初始指挥图标均在可视范围内。此项是镜头调整，尚未以逐关实玩确认所有边缘和不同兵力下的标记排列。

## 检查范围

只做启动资源延迟、单人联机大厅准备、缓存升级和源文件语法/素材依赖检查，没有反复跑整套游戏测试或长战役。未测量此次所有界面的公网首载速度或实玩帧率，不把原来的本机缓存时间冒充实际公网体验。
