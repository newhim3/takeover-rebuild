# 素材使用范围与单文件发布

日期：2026-10-09。范围：当前交付入口、国家/兵种/状态的动态素材分派、原地图脚本、UI/动画图集及备用路径。没有运行浏览器、战斗或完整动画回放；以下是静态可达性审计，不能当成画面全部实测。

## 结论

**没有把每个素材文件都接入正式画面，也没有理由把所有导出逐一显示出来。** 当前发布把整个素材目录带上，包含正式渲染文件、动态备用、原始构建源、匿名内部符号及历史导出。素材多、使用原素材、原版细节完整，是三个不同的问题。

当前素材共有 **12,540 个文件，656,448,581 字节（626.04 MiB）**。文件逐一与 `dist/lan-package-manifest.json` 对照，缺失文件、额外文件、长度差异均为零。这个数字不含 Node 运行环境、游戏脚本和 EXE；不能把以前压缩包体积与本次素材解压体积混用。

| 当前静态分类 | 文件数 | 体积 | 含义 |
|---|---:|---:|---|
| 明确路径与当前动态分派可达 | 975 | 187.36 MiB | 46 个明确路径、929 个按国家/关卡/兵种/状态动态解析的资源；条件成立时可请求，未证明每个已实际显示 |
| 动画包的原 PNG 回退 | 383 | 9.59 MiB | `AssetPacks.assign` 下载、查表或解码失败时读取，不能只因平时走 pack 就删掉 |
| 构建源、已整理原帧与历史中间导出 | 7,663 | 263.27 MiB | 原 SWF SVG 逐帧、生成 WebP 的原 SVG/位图、烘焙默认归属的地图、历史修补产物；不直接等于正式请求量 |
| 提取数据与构建索引 | 12 | 1.27 MiB | 原始数值、动画、地图、符号来源，运行读取其生成版本 |

## 哪些已经接入

- 战役与联机地图：按四国战役顺序和默认第 7 关联机地图追踪 25 个原地图脚本。原地图内部会按领地归属切换地形帧，因此没有只把默认国家那一帧算作需要。B 中央高地底图、归属遮罩及四国原地形纹理也在当前入口。
- 兵种与建筑：按真实兵种记录、科技等级、四个方向、行走/攻击/死亡与有原注册点的 `SpecialA` 分派。当前可达原符号为 754 个，包含兵种、建筑、士气及特效；这不是“754 个动画已实际回放”的声明。旧审计把死亡说成只用 Down 方向，已经不适用于当前代码。
- 原 UI：主界面、存档、国家旗帜、地图背景和城堡、招募/建造窗口、四国 HUD、条令、通关评级、结算国徽、统计条与经验帧。静态屏幕缓存索引有 212 项，本次明确对应页面分派的为 199 项；没有把整个索引都直接宣称显示过。
- 法术与操作反馈：技能指针、原弹体、普通法术与终极法术的特效/宣告页，命令和行动状态、士气。终极宣告正式播放缓存图集，保留的原 SVG 与嵌入位图是图集构建源。
- 音频：19 个音乐/操作/战斗/死亡/宝箱/士气事件资源有当前动态映射。其余 61 个声音没有在当前事件映射确认，不能说全部用上。

## 哪些没有直接加载，以及可能的用途

| 素材族或例子 | 当前为什么没有逐一直接显示 | 可能用途与处理方式 |
|---|---|---|

“构建源”不等于没价值，也不等于还必须在玩家电脑里直接加载。反过来，“索引里有”不等于游戏已实现对应行为和触发时机。

## 单个 EXE 和资源精简

单个 EXE 可以把运行环境、脚本、素材和启动流程封装到同一个交付文件。它改善的是下载与启动流程，**不会自动消除素材体积，也不会自动降低战斗或渲染开销**。若采用首次解包的方案，资源仍会存放到本机缓存，更新时按内容版本复用。

当前 111 个 `.pack` 共 38.83 MiB，其载荷包含 1,522 个原文件条目、合计 38.69 MiB 原图字节；同一原图可能在多个地图包出现。原 PNG 与 pack 并存，是为了少请求和可回退，不意味着有两套不同画面。原建筑 PNG 还被详情肖像直接读取，所以不能仅按 pack 索引删除全部原图。

另做精简发布的正确依据：

1. 开发目录继续保留全部资料；从发布白名单排除已确认的源档和历史中间导出。
2. 白名单必须覆盖四国、所有关卡、升级、死亡、法术、士气、结算，以及网络和图集失败时的必要备用。不能只记录一局正常游玩的请求。
3. 对未证实符号先定位来源；如果要去掉回退图，先改变并核对回退和建筑肖像依赖，再裁资源。
4. 明确保留常规单地图包与完整战役包的区别；此次允许从发布列表排除有明确证据的构建源，仍保留全部当前运行候选、通用备用及未证实资源，避免为了缩包引入缺图。

**187.36 MiB 的静态可达资源加上 9.59 MiB 备用，不能直接宣称就是最终可运行的最小包。** 没有完整实际资源覆盖记录，也没有验证裁剪版，暂不报告已达到某个缩包目标。

已生成保守发布白名单 `.tools/r26-publish-assets.json`：

- 保留 5,112 个素材文件、505,252,701 字节（481.85 MiB）。
- 从发布列表排除 7,428 个确定构建源/历史导出、151,195,880 字节（144.19 MiB）；开发目录原资料全部保留。
- 383 个已识别 PNG 回退、3,507 个未证实资源全部保留。另保留 212 个屏幕原 SVG 和 23 个 RenderUI 原图，保护通用 UI 分派的备用路径。
- 各排除项记录 `reason` 和 `backing`。原血量/交剑帧有保留的对应图集；原地图整屏有保留的地图脚本；原终极宣告 SVG/位图有保留的图集及时间轴；原 SWF 源档与历史导出不在运行解析目录。所有保留 SVG/JS/CSS 的相对依赖继续保留。
- `delivery-build.cjs` 启动时只读取 `delivery-manifest.json` 中的脚本/样式并合并，服务器只读取生成的 `game-data.js`；没有启动时再导出原素材的依赖。清单保留全部 manifest 中的 assets 脚本。

这些是白名单与依赖检查结果，尚未表示裁剪后的整局画面已经实玩验证。发布打包应读取该白名单、逐一核对文件存在和大小，不能删除本地素材目录。

## 复核文件

- `tools/audit-r26-asset-usage.cjs`：只读扫描；只写本报告对应的审计记录，没有删素材或修改运行代码。
- `.tools/r26-asset-usage.json`：每个文件的字节数、分类、引用/分派证据；含完整清单对照和 pack 条目统计。
- `.tools/r26-publish-assets.json`：保守发布白名单，排除原因、保留原画/数据的对应证据和备用保护检查。
- `delivery-manifest.json`：正式脚本/样式顺序；不直接改生成的 `game-shell.js/css`。

扫描使用 `fs.readdirSync(..., { withFileTypes: true })` 递归遍历所有常规文件，不按扩展名过滤。原导出文件名里的 `#` 保留为真实文件名；仅真正资源 URL 去除查询串，避免把匿名源文件漏统计。
