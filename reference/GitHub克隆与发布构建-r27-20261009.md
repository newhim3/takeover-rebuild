# 从仓库重建发布包

发布输入保存在仓库内。`config/runtime-assets.json` 记录保守审计决定保留的 5,112 个资源路径；它不依赖开发者电脑的 `.tools/r26-publish-assets.json`，也不以扫描完整资料作为每次发布的前提。原版素材与不确定用途的文件继续保留，未从开发资料中删除。

在 Windows 上安装 Node.js 24 或更新版本及 .NET Framework 4.6 或更新版本（建议 4.8）。单文件启动器的 AppContext 长路径开关依赖 4.6+；构建脚本会通过注册表 Release 值检查这个前置条件。仓库使用 Git LFS 时，先安装 Git LFS 并执行 `git lfs pull`，确保得到真正的图片与二进制文件，而不是 LFS 指针。缺失素材或未拉取的 LFS 对象会中止构建。

在仓库根目录执行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/build-release.ps1
```

脚本优先使用 `.tools/native/node.exe`。没有捆绑 Node 时使用 PATH 中的 `node.exe`，并复制到构建目录，供发行包启动器使用；不查找某个开发者的 Codex 私有路径。构建不会启动游戏、房间服务或公网隧道。

这个命令依次重建交付 JS/CSS、编译两个本地启动器和单文件启动器、验证版本化资源清单、生成逐文件 SHA-256、打包 ZIP，最后生成 `dist/城邦征战.exe`。Windows 内置 .NET Framework C# 编译器路径按系统目录查找，不依赖预编译的 EXE。C# 源码明确按 UTF-8 编译，避免中文内容随系统区域设置变化。

结果位于：

- `dist/城邦征战.exe`：供玩家直接分发的单文件版本。
- `dist/城邦征战-局域网便携版.zip`：相同游戏的完整运行目录。
- `dist/lan-package-manifest.json`、`dist/release-package.json`、`dist/single-exe-package.json`：版本与文件校验信息。

ZIP 在临时文件中构建。清单生成后若文件内容变化，或素材、依赖、启动器、Node 缺失，则发布失败；不会静默生成少文件的包。单 EXE 再次核对当前交付版本、清单和 ZIP 校验值。旧的成功发布文件不会被半成品替换。压缩时间戳、编译器和选用的 Node 版本可能让不同电脑生成的二进制哈希不同；这里保证构建输入可追踪和包内内容完整，不声称逐字节可复现。

## 调整资源清单

游戏增添资源时应同步审核 `config/runtime-assets.json`。该清单只决定发行范围，不能用来证明每个素材实际已经播放过。需要重新运行完整审计时，先生成包含全部素材的清单，然后审计，再导出小配置：

```powershell
node tools/build-lan-package.cjs
node tools/audit-r26-asset-usage.cjs
node tools/update-runtime-assets.cjs
```

最后复核并提交 `config/runtime-assets.json` 的变化。详细审计包含逐项理由并保留在 `.tools` 的开发记录中，玩家运行及正常发布不依赖它。新增文件不得未经核对地挤掉旧的运行资源、回退资源或不确定用途资源。
