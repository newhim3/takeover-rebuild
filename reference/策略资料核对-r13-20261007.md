# 策略资料与现有敌军行为核对

2026-10-07。本次只读研究，没有修改 `enemy-ai.js`、`difficulty.js`、`ai-presets.js`，没有运行长战役模拟。下列“已有”表示代码中存在相应分支，不等于所有实战情形已经验证。用户已经认可的十秒发展、集结、骚扰、回援、撤退和兵种偏好保留。

## 一手资料给出的方向

1. **比较行动的收益、风险和耗时。** Dave Mark 与 Kevin Dill 的 GDC 讲义把距离、威胁、生命等量转换为可比较的行动价值，并允许在候选项中加权随机选择。它也指出：所有条件都不满足时直接落入闲置行为，容易漏掉边缘情况。[GDC 2010：Improving AI Decision Modeling through Utility Theory](https://media.gdcvault.com/gdc10/slides/MarkDill_ImprovingAIUtilityTheory.pdf)，见第 32–35、50–55、59–60 页。

   项目已有：`objectiveScore` 比较距离、攻城耗时、守军比例、空城、建筑资源与宝箱；`chooseTask` 保留原任务，只有明显有利的新目标等情况才改令；`lootOpportunity` 排除正在交战、回援、低血量和危险路线。宝箱是经济机会，已有逻辑并非不断让主力追箱子。

2. **兵力评估需要战场情境，不能只数队伍。** Creative Assembly 的 GDC 演讲介绍以单位基础表现加情境修正来估计战斗能力，其中包含对手组成和地形等因素。[GDC 2018：Understanding Your Enemy: A Mathematical Approach to Unit Analysis](https://www.gdcvault.com/play/1025294/Understanding-Your-Enemy-A-Mathematical)。此次读取了官方演讲简介，没有声称看完完整录像。

   项目已有：`armyStrength` 同时使用剩余成员、当前生命、攻击间隔、盾墙、长矛克骑兵、冲锋、远程、状态和攻城加成。`targetAssessment` 先判断守军，再估算城墙耗时；困难以上考虑有限范围内、能及时到达的增援。研究支持继续核对这个估计，而不是给高难度单位额外血量或伤害。

3. **保留战略，预备失败时的应对。** 华盛顿大学与 Microsoft Research 的 RTS 论文把战略、战术与即时控制分层，并通过并行的预备行动应对反攻等风险；论文也明确讨论无法保证从任何状态获胜的情形。[AAMAS 2015：Selecting Robust Strategies in RTS Games via Concurrent Plan Augmentation](https://www.microsoft.com/en-us/research/wp-content/uploads/2016/12/RTS.pdf)，见第 1–3 页。

   项目已有：发展与付费补兵继续进行，回援、修理、恢复中的部队先从出击兵力中扣除；小分队骚扰与主力任务并存，危险或任务结束后返回安全据点。`send` 与 `waveOrders` 避免每次决策重启路径或取消攻击前摇。由此推断：更适合本项目的改进是查漏少数失效出口，而非把整个 AI 改成新的规划器。

## 已有难度递进的具体内容

| 行为 | 现有代码与边界 |
| --- | --- |
| 开局发展 | `offensiveOrders` 和新骚扰任务都受十秒限制；遭袭时 `reserveUnits` 允许防守。 |
| 真实经济 | `development`、`recruit` 通过建造、升级、招募的真实接口付款；保留战争预算，受压时优先补兵，人口不足建农庄。 |
| 有目标地搭配 | 根据目标守军和现有组成选择步兵、弓箭手、骑兵、攻城车、法师；攻城耗时较长才考虑为攻城车存款，远程目标才提高骑兵价值，没有固定采购配额。 |
| 乘虚与牵制 | 困难以上可分兵攻空虚据点；精锐以上增加对远程、攻城车和弱队的骚扰。分队任务带超时、危险撤回和再次派遣间隔。 |
| 协同与回援 | 长矛步兵找骑兵、骑兵找后排、远程利用前排掩护、攻城车避免超过前排；双线受压时按能否救下据点和到达时间排序，并保留短期回援承诺。 |
| 法术辅助 | 高难度更频繁评估施法，但仍检查解锁、钱袋中的法力、合法对象、重复覆盖和正在生效的区域；治疗、增益、控制、召唤、沙虫攻堡与四国大招分别择机。 |
| 稳定随机性 | 兵种偏好在一局内保留随机个性，目标随机偏差持久保存；候选排序随机不等于每个决策都改行军任务。 |

对应源码：`enemy-ai.js` 中 `armyStrength`、`targetAssessment`、`chooseTask`、`reserveUnits`、`development`、`desiredTypes`、`maneuverOrders`、`waveOrders`、`spellTarget`、`spells`；`difficulty.js` 中 `tactics` 和各模式配置。

## 不能省略的现状与后续定点检查

- **当前不是所有难度都完全同起始资源。** 普通没有加成；困难、精锐、噩梦分别保留此前获准的一次性开局金币/法力优势 `15/5`、`30/10`、`45/15`。普通以上没有在难度表中增加常规单位生命、伤害或免费技术领先。最新要求强调智慧带来的难度，本轮未擅自改这项历史配置，但汇报不能把现状说成“所有难度纯粹同等经济”。
- **两线回援的救援评估可以偏乐观。** `saveable` 最初按可能到达的帮手估算，随后实际派遣才扣除已分配人员。只读发现，不代表实际已有死锁；未来若出现回援选错，可以核对“评估人数”和“真正可派人数”，保留现有优先级和承诺时间。
- **搭配按整队数量衡量，战力按剩余成员衡量。** 半残部队仍算一队参与 `desiredTypes` 的数量统计，可能使购买建议与有效前排数量不完全一致。若用户反馈阵容失衡，先核对此处，不直接调国家基础伤害。
- **卡在集结阶段需要区分原因。** `offensiveOrders` 已扣除保留部队并在安全据点等待；若部队永不出击，应检查可达路线、真正可用人口、目标援军预测与购买预算是否同时阻塞。不能为掩盖失效而强迫 AI 送兵，或取消开局十秒规则。
- **有关卡可通关与难度的承诺需要实玩证据。** 现有付费规则与战术分支能够提供策略空间，但源码阅读和路径检查无法证明每一关既不无解又不简单。优先核对初始资源、可争夺据点、关键道路与技能合法性，再依据用户实玩反馈修具体关卡；此次没有宣称完成全关平衡验证。

上述后续点均为基于源码的推断，不是论文直接给本游戏的结论，也没有在本轮写入敌军逻辑。
