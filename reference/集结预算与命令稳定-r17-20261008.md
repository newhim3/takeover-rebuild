## 已确认的冲突与修改

| 实际冲突 | 处理 |
| --- | --- |
| 升堡预算会扣留整笔 150/300 金币，主攻还缺兵时也不招募 | 当前任务缺兵或需要防守时，优先保留下一批真实付费兵力的预算，延后升堡；其他升堡储蓄限制在约八秒可见己方收入以内。正常训练间隔与真实费用沿用当前配置 |
| 两队主力抽走一队去骚扰，剩下的主力永久达不到出击条件 | 分队前检查主攻剩余人数与对守军的力量；精锐、噩梦进一步比较集中与分兵的估算战损。拆掉主攻条件的分队不成立，已执行的分队在条件消失时明确撤回 |
| 可见援军预判只影响选目标，实际出击却只计算当下守军 | 出击也计入同一份有时间、人数上限的可见增援预判 |
| 换目标、前进和退回没有足够稳定区间 | 目标采用八秒基本承诺，严重劣势允许提前另选可行目标；攻击中的明显局部劣势持续三秒才重新集结，重新集结至少五秒。既有可挽救据点排序与兵种协同保留 |
| 同一移动目标仅位置变化就被当成新命令 | 以目标 ID 判断原任务是否相同，不反复重新准备攻击；实时跟踪位置交给已有交战寻路 |
| 主力已在前方集结，换任务却强制回城堡集合 | 若前方一组集中兵力已经满足出击条件，直接以该组所在位置为集结点继续前进；弱小先锋仍需等主力 |
| 防守部队会被主攻、恢复和下一次防守重复改令 | 当前据点的防守队先作为已承诺防守力量，避免打断既有攻击；危险结束后先返回本堡，保留短暂防守承诺，再允许明确调兵 |
| 群体移动为了间距把后续部队的终点截短最多 80 | 所有选中部队保留同一个点击目的地，行进间距继续由已有移动避让处理 |
| 空路径被直接当作完成，远未到终点就清令 | 比对可行走目的地；没到达时保留新命令，每 0.35 秒最多重试一次路径。手动改令仍覆盖旧目的地 |
| 城堡出战范围 160，大于入驻争夺范围，路过的敌人引发上下塔 | 引擎与 AI 共用据点威胁判断；门口真正的侵入、正在攻击守军、针对据点的攻城命令会迎敌。远程攻城车仍可立即触发出战；向外离开的路过单位不会因旧大范围触发出战 |
| 双方已撤退，残留交战对象又触发驻军出战 | 据点的交战威胁判断同样排除双方正在撤退的旧接触对象 |

## 明面经济与集中兵力判断

`ai-economy-intel.js` 每个决策间隔观察可见据点、附属建筑、科技升级和新出现的部队，累计产出与消费区间。占领已建建筑、同一单位 ID 转换阵营不会被重复当成购买。初始资金、折扣、宝箱、退款与召唤都有不确定性，因此估算是区间；不会访问对方 `factions.gold`、实际队列、私有条令或已付款费用。

困难以上会给资源重地与预期战损增加目标权重；精锐、噩梦进一步根据可见支出和经济估计增援风险。风险仅影响目标评分，不会凭空添加守军。付费补兵、经济建筑、升堡和分队均参考当前任务，保留兵种选择随机性与原训练节奏。骑兵、攻城车继续按目标及克制需求选择。

`ai-combat-planner.js` 使用当前生命、有效伤害速度与集中攻击的近似模型比较战损；每次最多处理 32 个消灭事件，超过上限使用剩余总生命与伤害估算。它不推进真实战斗、不进行客户端伤害预测；分队比较缓存同一组兵力的结果，只在既有 AI 决策时钟调用。该模型不是原版数值表，也不是机器学习训练成果。

参考 [Combat Models for RTS Games](https://arxiv.org/abs/1605.05305)、[Approximation Models of Combat in StarCraft 2](https://arxiv.org/abs/1403.1521) 关于轻量战斗预测的研究，以及 [0 A.D. PETRA 进攻计划源码](https://raw.githubusercontent.com/0ad/0ad/master/binaries/data/mods/public/simulation/ai/petra/attackPlan.js) 中明确任务、集结点及兵力要求的设计。只借鉴思路，未复制实现，也未将本项目的估算公式冒充论文公式。

- 保留所有难度的十秒发展期；遇袭仍能防守。普通资源与真实费用相同，高难度原先小额一次性起始资源不扩增。
