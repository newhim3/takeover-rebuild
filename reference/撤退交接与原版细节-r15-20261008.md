# 撤退交接与原版细节 r15

2026-10-08。运行脚本已更新并重新生成交付文件。本轮修改接敌和撤离的交接及显示，不改敌军的目标选择、招兵偏好、经济、难度调度或兵种平衡。五个受保护文件与 `.tools/r10-ai-baseline.json` 完全一致。

## 战斗中的撤离

| 实际情况 | 本轮行为 |
| --- | --- |
| 两队都在沿各自路线远离对方 | 停止互相攻击，取消未命中的旧攻击，继续各自目的地 |
| 一队想打，另一队撤离 | 撤离队在直接接触时反击，同时继续撤离，不重新追杀对方 |
| 回堡恢复的队伍接触敌人 | 原回堡目的地保留，允许接触反击；敌人挡住正面时先交战，不能穿兵 |
| 双方撤离时第三队仍在攻击 | 仍可以反击第三队，不把所有敌人一起忽略 |
| 撤离时发动反击 | 攻击姿态朝向攻击对象，行军朝向仍跟随撤离路线；联机同步攻击朝向 |

判断依据是当前保留路径下一段是否远离对方，而不是把所有移动命令都当成撤退。直接进攻对方的命令、冻结、击退和城内队伍不误判为撤离。新命令的目的地不被旧追击覆盖。僵尸的接敌冲刺也不再在背向敌人的撤离中错误启动；没有修改原冲刺倍率。

定点检查：`tools/check-withdrawal.cjs` 中九个短场景，包括双方撤离、单方反击、旧攻击取消、正面阻挡、第三方攻击和回堡路径保留。每个仅计算短步长，未运行敌军决策或长战役模拟。

## 仍有明确用途、尚未接入的细节

- `ASTChargingClass`、`ASTSleepingClass`、`ASTDefendingAndAttackClass`：原冲锋、休息和城内反击提示。现行状态需要与原触发条件继续核对，不能把所有骑兵都标成冲锋、所有闲置部队都标成睡眠。
- 中毒/冻结色变换：原源码分别增加绿色或蓝色通道，毒优先。需要缓存后的成员图色变换及联机状态字段，不应每帧处理所有兵的像素而拖慢渲染。
- 攻城命中时序：目前网页仍先结算远程伤害，再播 0.28 秒投射表现。这次将爆炸放在该表现末尾，没有改伤害时序。对城堡的攻击当前没有走部队溅射分支，不能声称本轮覆盖所有城堡命中动画。
- 原地图边缘修补、第四国战役数据及部分界面适配仍有先前记录的限制，本轮没有改地图或重新设计这些页面。
